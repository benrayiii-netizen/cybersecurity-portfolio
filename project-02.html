PROJECT 02 • IDENTITY SECURITY • DETECTION ENGINEERING

Suspicious Login Detector

Identity-threat detection with behavioral rules, threat-intelligence enrichment, risk scoring, API analysis, and SOC-oriented alerting.

Python FastAPI Threat Intelligence Risk Scoring Docker

The Problem

Identifying risky authentication behavior

Authentication logs can contain early indicators of account compromise, including repeated login failures, successful access following failures, unusual geographic locations, and successful authentication outside expected hours. Analysts need a way to turn these individual signals into prioritized alerts.

The Solution

Multi-signal login threat detection

The detector analyzes authentication activity using multiple detection rules and enriches login events with local threat intelligence. Findings are assigned categories, severity levels, and risk scores to help prioritize analyst investigation.

Brute Force Detection

Detects multiple failed authentication attempts associated with the same source.

Account Compromise

Detects successful authentication occurring after recent failed login attempts.

Location Analysis

Identifies authentication activity from unusual geographic locations.

After-Hours Detection

Flags successful authentication occurring outside expected operating hours.

Detection Engineering

Multiple signals provide stronger context

Known Bad IP Activity

Source IP addresses are compared with local threat-intelligence data to identify known suspicious infrastructure.

Severity Assignment

Findings are classified using Critical, High, and Medium severity levels based on detected behavior.

Risk Scoring

Alerts receive numerical risk scores so the most important activity can be investigated first.

API Logging

API requests can be logged to support operational visibility and investigation.

Detection Evidence

Three alerts from one suspicious login

A successful after-hours login from a known suspicious geographic source was analyzed after three recent authentication failures. The detector generated three separate findings: Possible Account Compromise, Unusual Location, and After Hours Login.

Engineering Lessons

Context changes the value of an alert

A single authentication signal may not provide enough context for an analyst. Combining recent failures, successful authentication, geographic information, time-of-day behavior, and threat intelligence produces a more useful security picture.

This project demonstrates how detection rules, enrichment, severity classification, and risk scoring can transform raw login activity into actionable identity-security alerts.

Future Improvements

Expanding identity-threat detection

Future development can include impossible-travel detection, user and entity behavior analytics, device reputation, MFA context, cloud identity logs, centralized SIEM ingestion, external threat-intelligence feeds, and automated integration with the SOC alert correlation engine.
